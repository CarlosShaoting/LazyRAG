# 产品方案与交付

## 场景说明

这是从 `product-solution-delivery` Skill 适配而来的两层 Router 工作流。

第一层是父 Router，按照“显式阶段选择 > 高置信度确定性规则 > 模型推荐”的顺序，从产品方向、
竞品与生态位、产品方案、PRD、交互原型、方案评审和研发交付中选择本轮唯一阶段。用户明确提出
连续任务时，后续阶段只登记为计划；当前 Workflow Session 仍只执行 `selected_stage`。

第二层只在第一层选择 `design` 时运行。它按产品机制与产品体验下的六类设计对象确定主责范围和
联动范围，并根据做错代价/可逆性、实践发散、影响/耦合和不确定性，为每个子决策选择 `light` 或
`heavy`。隐私、身份、权限、静默写入、跨租户和高损失不可逆动作会强制进入重型路径。

详细来源、业务合同映射、LazyMind 原生替代和能力边界见 `SOURCE.md`。

## Workflow 启动参数

- 产品目标必须明确；阶段可以显式选择，也可以交给父 Router 判断。首次 Ask user 完成后，
  没有显式阶段、既有项目产物或上传材料的全新项目固定先进入产品方向；方向交付并经用户确认
  继续后，竞品与生态位是默认下一阶段。显式选择与已有项目续跑仍可从任意支持阶段进入。
- `execution_depth=auto` 由当前子 Skill 根据材料判断；用户可明确指定深度偏好。
  父阶段深度不覆盖设计 Router 的 `light/heavy` 研究强度。
- 篇幅默认按阶段设置；存在样例时复用，不存在则使用默认结构。用户可随时明确覆盖这些设置，
  但不作为重复启动问卷。此项目默认策略按用户“同窗口完成全流程、不补填其他内容”的要求，
  明确替代 portable Skill 的逐产物类型样例提问；不会谎称用户提供了样例或确认了业务事实。
- 用户材料和参照样例只绑定为文件输入；标量参数保持值传递。
- 必要上游产物不存在时，用户可补充等价材料，或明确授权形成标注缺口的草稿。

## 数据流与人工控制

1. `route_product_stage` 只加载父合同、生成并校验路由记录，并把项目内已绑定材料整理成封闭证据交接；
   Router 不执行外部检索。全新项目在 Ask user 后默认选择产品方向；真正的取证只在所选业务阶段内发生。
2. 非设计阶段直接进入对应的唯一业务分支；不存在七阶段串行图或 `skip_if` 裁剪。
3. `design` 先进入 `route_design_scope`，经用户确认范围后再进入轻量或重型取证分支，两者汇合到
   同一个 Writer 方案大纲与正文流程。
   两层 Router 均由宿主依据已保存的 JSON 字段绑定唯一实际出口。轻量取证遇到升级信号时，
   在当前设计阶段内升级对应子决策并传递 `design_escalation`，不要求重新开始产品阶段。
4. 方向、方案、PRD、评审和交付阶段使用 LazyMind Writer：大纲和正文分别保留人工编辑/继续边界。
5. 七个阶段都生成同一逻辑产物的 HTML 与 Markdown；HTML 是默认交互视图，Markdown 可编辑下载。竞品与原型也必须成对发布。
6. `finalize_product_delivery` 为本轮唯一汇合点，内部登记 Artifact Manifest 和 Product Workspace，
   将状态停在 `awaiting-stage-confirmation`，只向用户展示自然语言交付摘要。
7. 每个业务阶段保存独立的内部质量评估，记录实际核验、必要依赖、缺口和决定状态。没有实际
   核验的项目不能标为通过；材料缺失或版本冲突不能仅凭生成了文件就登记为正式产物。
8. 用户通过阶段操作区或明确聊天指令继续/切换，宿主 `product-stage-relay` 幂等创建新 Session，
   用隐藏 `workspace_seed`、`stage_approval` 和 `upstream_*` 输入传递状态与精确版本。
   旧 Session 和旧产物保留；接受当前产物是单独授权，不把继续操作等同于接受所有决定。
9. 对用户始终是同一个项目、同一个会话窗口。方案、PRD、原型等是该项目的不同共享视图，
   不是相互覆盖的一篇文档，也不是需要重新上传材料的独立任务。共享视图可查看历史阶段的
   当前选定版本；进入某阶段修改时自动复用该阶段上一版及相关上游，保存新版本。
   最新阶段补充要求由宿主写入 `stage_approval.request_context`；项目目标保持稳定。
10. 内容版本与质量评估版本分别记录：正文没有变化时仍可更新核验结果；核验失败不能沿用旧的
    通过结论。内部评估与批准记录不显示成测试回执。查看旧视图不等于授权修改或运行下一阶段。
11. 每个模型步骤由宿主执行策略限制最大轮次、整步截止时间、重复调用和单工具调用次数；提示词
    只能缩小这些边界，不能放宽。Writer 同时具备单章和整篇截止时间，失败后不进入通用文件漫游。

## 能力边界

工作流不声称登录态产品操作、付费资料访问、浏览器视觉 QA、生产前端实现、技术架构、研发
估时、发布日期或组织审批。继续、切换或返回上游都需要用户明确动作，并在同一会话中的新
Workflow Session 执行；这是内部执行边界，不会要求用户新开窗口。运行中可查看共享视图，
但不静默中断正在执行的阶段。runtime trace、内部 Manifest/Workspace 和路径不展示在用户正文中。
